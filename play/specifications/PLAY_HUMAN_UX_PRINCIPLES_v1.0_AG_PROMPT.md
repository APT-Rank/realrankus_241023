# AG PROMPT — PLAY HUMAN UX PRINCIPLES v1.0

## Objective

Read and register `PLAY_HUMAN_UX_PRINCIPLES_v1.0.md` as the fixed Product Experience baseline for all future PLAY Human UX work.

Do not redesign, reinterpret, weaken, or silently modify it.

## Required fixed decisions

- Q1 = **A + C + D**
- Q2 = **E 중심 + A/B/C/D**
- Q3 = **C → D → E**
- Q4 = **A + B + C + D + E**
- Q5 = **E + C + D + A**

Interpretation:
- Start with 700M KRW so the user knows what they can operate.
- Establish comparable other participants.
- Establish a moving economic world.
- Make “something I have not discovered yet” the primary exploration driver.
- Discovery should lead to context, new possibilities, observation of others, and user choice.
- Actions must produce understandable results and new possibilities.
- Economic achievement is part of the final value.
- Push notifications are part of re-engagement and must be user-controllable.

## Master UX loop

`ECONOMIC WORLD → DISCOVERY → CURIOSITY → EXPLORATION → JUDGMENT → ACTION → RESULT → ACHIEVEMENT / COMPARISON / SELF-DISCOVERY → NEW POSSIBILITY → NEW CURIOSITY → DISCOVERY`

Push bridge:
`MY RESULT / MY INTEREST / WORLD FLOW / OTHER PARTICIPANTS → PUSH → “WHAT HAPPENED?” → PLAY RETURN → DISCOVERY`

## Mandatory evaluation

For every future UX proposal check:
G1 what the user has; G2 reason to explore; G3 new discovery; G4 meaningful choice; G5 visible consequence; G6 new question; G7 other participants; G8 achievement; G9 return reason; G10 notification control.

If a proposal conflicts with the principles, flag the conflict and STOP for Product Owner review. Do not silently ship it.

## Push requirements

Support these categories:
1. My Result
2. My Interest
3. World Flow
4. Other Participants / Season

At minimum provide ON/OFF controls for all notifications and each category. Where appropriate support Immediate / Daily Summary / Important Changes Only / OFF.

Push must create curiosity from a relevant change, not advertising or forced engagement.

## Product character

Do not turn PLAY into:
- a static dashboard,
- a prescriptive “correct answer” game,
- quest spam,
- notification spam,
- pure wealth ranking,
- a dead world,
- action without consequence,
- consequence without explanation.

## Protected areas

Do not modify verified Economic Engine, Property Market, Reliability, GATE 4/5/6, or verified Research Logging logic as part of UX work.

If UX requires a change to a verified area: STOP and report the affected area, reason, risk, proposed change, and required approval. No workaround.
