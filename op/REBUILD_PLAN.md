# 오피스텔랭크 개선 리빌드 계획

## 목표

`/op/`의 현재 오피스텔 서비스를 그대로 운영하면서, 루트 `index.html`의 최신 서비스 경험과 기능 구성을 오피스텔 데이터에 맞게 적용한 개선판을 별도 경로에 구축한다. 새 버전은 기존 화면과 배포 자산에 영향을 주지 않고 독립적으로 검토·운영할 수 있어야 한다.

## 기준 화면과 현재 차이

- 기준: 루트 `index.html` 및 그 페이지가 사용하는 최신 공통 기능
- 대상: `op/index.html`과 오피스텔 전용 정렬·검색·상세 데이터
- 현재 오피스텔 화면은 시도/시군구/월 선택, 단지·지역 검색, 정렬, 단지 및 지역 상세 분석을 제공한다.
- 루트 화면에는 통합 단지 검색, 지도와 목록 전환, 지도 필터, 단지 비교, 추가 분석/시각화, 개선된 반응형 셸과 공통 탐색 기능 등이 있다. 이를 그대로 복제하지 말고 오피스텔 데이터에 맞춰 재구성한다.
- 구현 전 루트 화면의 실제 기능과 최신 스크립트 의존성을 다시 확인해 이 목록을 확정한다.
- 기능 기준은 루트 `index.html`과 그 페이지가 실제로 불러오는 전용 스크립트로 확정한다. 오피스텔 데이터에 적용할 수 있는 기능은 이름과 흐름을 임의로 축소하지 않고 데이터 계약에 맞춰 이식한다.
- 시각 기준은 기존 오피스텔 서비스의 남색 `#293249`이다. 루트 서비스의 기능 구조는 참고하되 브랜드 색상은 바꾸지 않는다.

## 범위

### 포함

- 루트 서비스에서 제공하는 탐색·검색·정렬·지도/목록·상세 분석 흐름 중 오피스텔 데이터로 성립하는 기능
- 오피스텔의 기존 지역 및 월별 랭킹, 점수, 실거래, 교통·생활·인프라·교육·지역 분석
- 오피스텔 단지 간 비교 기능(비교 대상과 지표는 오피스텔로 한정)
- 기존에 필요한 로그인/권한 처리, 공유, 안내, 반응형 레이아웃과 접근성 개선
- 필요한 경우 버전 전용 웹앱 매니페스트와 서비스 워커

### 제외

- 게시판, 댓글, 게시물 작성·조회 및 관련 운영 UI/API
- 좋아요, 즐겨찾기, 추천 등 좋아요 상태를 만들거나 저장하는 기능 및 관련 UI/API
- 위 제외 기능을 위해서만 사용되는 로그인 상태·Firestore 구독·데이터 구조

로그인이 상세 분석 등 다른 포함 기능에 필요하다면 유지한다. 제외 기능과 공유되는 인증 코드는 의존 여부를 확인한 뒤 안전하게 분리한다.

## 별도 버전 운영 방식

- 새 진입 경로는 `/op/v2/`로 둔다. 기존 `/op/` 및 `op/index.html`은 리빌드 과정에서 수정하거나 대체하지 않는다.
- 새 버전의 HTML, 전용 CSS/JS, 매니페스트, 오프라인 페이지, 서비스 워커를 새 경로 안에 둔다. 기존 공통 자산은 읽기 전용으로 재사용하고, 개선에 필요한 변경은 버전 전용 파일로 만든다.
- 새 버전의 분석 태그, canonical/OG URL, 아이콘, 데이터 경로와 캐시 키가 `/op/v2/`에 맞는지 분리 확인한다. 서비스 워커가 기존 `/op/` 또는 루트 캐시를 덮어쓰지 않도록 범위와 캐시 이름을 고유하게 둔다.
- 데이터 로더는 기존 오피스텔 데이터 계약을 우선 사용한다. 루트 아파트 데이터 전용 필드와 경로를 직접 참조하지 않도록 데이터 접근 계층에서 필드를 변환·검증한다.
- 공개 전에는 `/op/v2/`를 검토용 주소로 운영한다. 기능·데이터·모바일 동작을 확인하고 전환 여부를 별도로 결정한다. 그동안 `/op/`는 현행 그대로 유지한다.

## 실행 단계

1. **기능 및 데이터 기준선 확정** — 루트 기능 목록과 `op`의 HTML/JS/CSS·데이터 스키마를 대조한다. 기능별로 `그대로 적용`, `오피스텔용 변환`, `제외`를 표시하고, 게시판·좋아요 관련 호출과 스타일 의존성을 찾아 목록화한다.
2. **독립 골격 구축** — `op/v2/`에 새 진입 페이지와 전용 자산을 만들고 지역/월 선택, 공통 내비게이션, 로딩·오류·빈 결과 상태를 세운다. 기존 서비스 파일은 건드리지 않는다.
3. **핵심 탐색 이식** — 오피스텔 데이터 어댑터를 먼저 정리한 뒤 지역·월별 목록, 전국/지역 단지 검색, 지역 검색, 정렬과 필터를 이식한다.
4. **지도와 상세 경험 개선** — 목록/지도 전환, 지도 마커·필터, 단지 상세 차트와 실거래, 지역 분석 및 공유를 연결한다. 아파트 전용 지표·문구는 오피스텔 지표로 바꾼다.
5. **비교와 부가 분석** — 오피스텔 단지 비교 및 적용 가능한 분석 도구를 구현한다. 아파트 전용 비교·차트 기능은 데이터 정의를 확인해 오피스텔 버전으로 변환할 수 있을 때만 반영한다.
6. **제외 기능 및 운영 설정 정리** — 새 페이지에서 게시판/댓글과 좋아요/즐겨찾기 UI·호출·데이터 구독이 없는지 점검한다. 인증은 남은 기능에서 필요한 최소 경로만 연결하고, 버전 고유 PWA·SEO·분석 설정을 완료한다.
7. **검토 및 별도 공개** — 주요 지역과 월, 검색 결과 없음, 상세 진입, 모바일/데스크톱, 지도/목록, 비교, 로그인 필요 흐름, 오프라인 캐시를 확인한다. 현행 `/op/`와 리소스 경로·서비스 워커가 서로 간섭하지 않는 것을 확인한 뒤 `/op/v2/`를 검토용으로 공개한다.

## 완료 기준

- `/op/`의 파일과 사용 흐름이 리빌드로 변경되지 않는다.
- `/op/v2/`가 오피스텔 데이터로 핵심 탐색부터 상세 분석까지 동작한다.
- 기준 화면에서 가져올 수 있는 기능이 오피스텔 의미에 맞게 반영되며, 미적용 기능과 사유가 기록된다.
- 게시판/댓글 및 좋아요/즐겨찾기 기능의 UI와 백엔드 호출이 새 버전에 없다.
- 새 버전의 캐시·배포 설정이 기존 서비스와 분리되어 있고 직접 URL로 접근 가능하다.

## 주요 주의점

- 루트와 `op`는 이름이 비슷한 기능도 데이터 모델·점수 산식·지역 단위가 다를 수 있으므로 화면 복사만으로 이식하지 않는다.
- 전역 스크립트와 DOM ID를 공유하면 두 버전의 개선이 기존 페이지에 영향을 줄 수 있다. 새 페이지의 ID/초기화 코드를 독립적으로 두고 공유 자산 수정은 피한다.
- 기존 오피스텔 페이지에는 페이지 내부에 큰 인라인 로직이 있다. 새 버전은 기능 단위 파일과 데이터 경계를 두어 원본의 복잡성을 그대로 늘리지 않는다.

## 1차 구현 현황

- `/op/v2/`에 독립 진입 페이지와 전용 스타일, 검색/비교 기능, 매니페스트, 오프라인 화면, 서비스 워커를 추가했다. 현행 `/op/` 파일은 수정하지 않았다.
- 기존 오피스텔 목록·상세 분석을 유지하면서 지도/목록 전환, 오피스텔 최대 3개 비교, 전국 단지 검색을 추가했다.
- 전국 검색은 필요할 때 색인 파일을 불러오며, 현재 색인은 2026년 10월 자료다. 자료 월을 갱신할 때 `node op/v2/tools/build_search_index.cjs YYYYMM`으로 해당 월 색인을 만든 뒤 화면의 검색 기준 월을 함께 갱신한다.
- 지도에는 등급 필터를 연결했고, 지도와 목록이 같은 필터 결과를 사용하도록 했다.
- 루트의 동별 아파트 GLI 차트는 아파트 거래 자료와 지표를 전제로 하므로 그대로 재사용하지 않았다. 대신 선택 지역의 오피스텔 자료로 동별 평균 입지 점수와 평단가 산점도를 만들고, 차트 이미지 저장을 추가했다.
- 이 차트는 현재 선택 지역 데이터만 사용한다. 사용자가 데이터를 볼 때 표본 수와 실거래가 있는 단지 수를 함께 확인하도록 안내한다.

## 단계별 확인 기록

### 1단계 — 기본 화면과 초기 상태

- 구현 상태: 개선본 첫 화면은 `/op/v2/`에 분리한다. PC는 기준 화면처럼 좌측 600px 목록과 우측 지도로 나누고, 모바일은 지도 우선 표시 후 하단 버튼으로 목록/지도를 전환한다. 남색 `#293249`을 유지하고, 지도 마커에 오피스텔 등급·점수·최근 거래가를 표시하며 현재 위치 이동 버튼을 둔다. 통합 검색과 최근 검색, 로딩 상태도 연결한다.
- 진단 후 수정: 사용자가 제공한 화면 측정값에서 지도 영역 높이가 0px임을 확인했다. SDK와 좌표 데이터는 정상이다. CSS 높이 지정만으로 반영되지 않을 가능성에 대비해 PC/모바일 작업 영역과 지도 캔버스 크기를 런타임에 직접 설정하고, 화면 크기 변경 때 네이버 지도 `setSize`를 호출하도록 보강했다. 지도 마커에는 등급·점수·최근 거래를 표시하고 현재 위치 버튼을 추가했다.
- 하단 메뉴: 레퍼런스 소스의 실제 분기를 반영한다. 바깥 `linkToAptrank_bottom`은 전체 폭이며, PC 내부 탭은 가용 폭에 맞춰 나누고 모바일 내부 탭 줄은 75px × 9개(675px)로 가로 스크롤한다. 하단 메뉴 높이만큼 지도/목록 작업 영역을 줄인다.
- 확인 포인트: PC에서 좌측 목록과 우측 지도가 동시에 보이는지, 지도 마커/현재 위치 버튼이 보이는지, 모바일에서는 지도가 먼저 나오고 하단 버튼으로 목록/지도가 전환되는지 확인한다. 기존 `/op/` 화면이 유지되는지도 확인한다.
- 데이터 기준: 기본 목록/지도 표시용 이름·점수·주소·좌표·최근 거래·검색코드는 현재 오피스텔 JSON에서 확인된다. 방문 집계는 별도 Firebase 권한이 필요하며 로컬 환경에서는 `Permission denied`로 표시되지 않을 수 있다. 이 값은 초기 목록/지도 표시의 필수 데이터가 아니다.
- 사용자 확인 상태: 런타임 크기 보정을 반영했다. 최신 CSS/JS가 로드된 뒤 지도 높이가 양수로 바뀌는지, 지도 타일이 표시되는지 사용자 브라우저에서 확인이 필요하다.

### 루트 기능 대조 기준

- 포함 후보: 통합 전국/지역 검색과 최근 검색, 정렬·필터, 지도/목록 전환과 지도 보조 도구, 단지 상세·분석·비교, TOP300 계열, 리포트 신청, 공유·알림·다국어 등 루트 페이지의 실제 사용자 기능.
- 제외: 게시판/댓글/작성·조회, 좋아요/즐겨찾기/추천과 이 기능들만을 위한 구독·저장 호출.
- 이식 원칙: 루트 스크립트가 아파트 데이터 또는 아파트 순위 파일을 직접 읽는 경우 그대로 포함하지 않고 오피스텔 스키마와 데이터가 뒷받침되는지 확인한 뒤 전용 데이터 어댑터로 이식한다. 현재 기능별 대조 및 누락 확인을 진행 중이다.
